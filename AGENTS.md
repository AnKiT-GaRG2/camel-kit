# Camel-Kit AI Agent Guidelines

These rules apply to all AI agents and harnesses used to contribute to this repository.
They follow [Apache Camel's attribution rules](https://github.com/apache/camel/blob/main/AGENTS.md#attribution)
and the [ASF Generative Tooling Guidance](https://www.apache.org/legal/generative-tooling.html).

## Attribution

- All AI-generated content, including issue and PR descriptions, review comments,
  inline comments and replies, MUST clearly identify itself as AI-generated and
  mention the human operator.
- Never guess the operator's name. Determine the authenticated GitHub username with
  `gh api /user --jq '.login'`. If the lookup fails, omit the operator rather than
  inventing a name.
- AI coding agents MUST be configured to add AI co-authorship trailers to commits,
  including documentation-only commits. For Claude Code, this can be configured in
  its [attribution settings](https://code.claude.com/docs/en/settings#attribution-settings).
- Use the identity of the agent that actually contributed, regardless of provider
  or harness. Never invent an attribution email or copy another agent's identity.
  Credit each contributing agent when multiple agents were involved.
- Bot reviews require the same explicit disclosure; bot authorship alone does not
  replace it. Preserve existing attribution when editing public content.

Use these templates consistently, substituting the actual agent identity and
verified operator:

- Commits: `Co-authored-by: ${agent name} <${agent email}>`
- Issue/PR descriptions and comments:
  `_AI-generated by ${agent name} on behalf of @${operator login}._`
- If the operator lookup fails: `_AI-generated by ${agent name}._`

The disclosure identifies the tooling and operator; it does not claim that a human
has reviewed or approved the content.

## Merge attribution

If any commit in a PR was AI-assisted, the squash-merge commit message MUST include
the AI co-authorship trailer. Preserve attribution when preparing other merge
commit messages as well.
